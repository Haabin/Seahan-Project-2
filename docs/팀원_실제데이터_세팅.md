# 팀원 실제 데이터 세팅

설비현황·금형교체 담당 브랜치(`feature/equipment-mold`)와 같은 개발 환경을 **명령 하나**로 맞춘다.
원료(씨벌크)는 범위 밖이라 이 세팅에 들어 있지 않다.

> ⚠ **내 개발용 Supabase 에서만 실행한다. 운영 DB 에서는 절대 실행하지 않는다.**
> 명령이 처음에 연결된 Supabase 프로젝트 ID 를 보여 주고, 그 ID 를 직접 입력해야 다음으로 넘어간다.
> 다른 프로젝트라면 입력하지 말고 멈춘다(틀리게 입력하면 아무것도 쓰지 않고 끝난다).

## 무엇을 맞추나

`npm run setup:real-data -- <운용안 경로>` 가 순서대로 한다.

1. 연결된 Supabase 프로젝트 ID 확인 (직접 입력)
2. `db:migrate` (적용 안 된 마이그레이션만)
3. 운용안 가져오기: 미리보기 요약 → `yes` 입력 시 적용. 이미 같은 내용이면 "변경 없음"으로 건너뜀
4. 교체 계수: `config/changeover-defaults.json`(PET1 B/M 2h, FULLSET 6h + 익일가동 끔). 현재 값 → 바꿀 값 표 → `yes` 입력 시 적용. 이미 같으면 건너뜀
5. 결과 요약 (호기·제품 수, PET1 계수, 마이그레이션 버전)

같은 명령을 다시 실행해도 된다. 이미 맞는 부분은 건너뛰고, 다른 부분만 최신으로 맞춘다.

## 준비물 (git 에 없는 파일 2개)

설비현황·금형교체 담당자에게 받아 **`data/samples/`** 에 둔다. 실제 자료라 git 에 올리지 않는다(`.gitignore` 대상).

| 파일 | 위치 |
|---|---|
| `제품배치운용안.xlsx` | `data/samples/제품배치운용안.xlsx` |
| `equipment-rules.json` (설비 제조사 규칙) | `data/samples/equipment-rules.json` |

`.env.local` 에는 **내 개발 Supabase** 의 `DATABASE_URL` 등이 있어야 한다(`.env.example` 참고).

## (가) 처음 세팅

```bash
# 1. 위 파일 2개를 data/samples/ 에 둔다
# 2. 패키지 설치
npm install
# 3. 세팅 (프로젝트 ID 확인 → yes 입력)
npm run setup:real-data -- data/samples/제품배치운용안.xlsx
```

## (나) 예전 버전을 이미 받은 경우

예전 버전으로 이미 세팅했어도 아래만 하면 최신 상태가 된다.

**merge 전에 내 변경을 먼저 커밋한다.** 커밋하지 않은 변경이 있으면 merge 가 멈추거나 변경이 섞인다.

```bash
# 0. 내 변경 먼저 커밋
git status
git add <내가 바꾼 파일들>
git commit -m "내 작업 저장"

# 1. 담당 브랜치 최신 코드 받기
#    (equipment 리모트가 없다면 한 번만: git remote add equipment https://github.com/hwangcy022/Seahan-Project-2.git)
git fetch equipment feature/equipment-mold
git merge equipment/feature/equipment-mold

# 2. 패키지 설치 (새 패키지가 있을 수 있음)
npm install

# 3. 세팅 다시 실행 (이미 맞는 부분은 "변경 없음"으로 건너뜀)
npm run setup:real-data -- data/samples/제품배치운용안.xlsx
```

**merge 충돌이 나면** 직접 고치지 말고 Claude Code 에 "merge 충돌을 해결해 줘"라고 요청한다.
해결 뒤 `npm test` 로 확인하고 커밋한다.

## 멈췄을 때

| 메시지 | 할 일 |
|---|---|
| 운용안 파일이 없습니다 / 설비 규칙 파일이 없습니다 | 담당자에게 파일을 받아 `data/samples/` 에 둔다 |
| 입력한 ID 가 다릅니다 | 연결된 프로젝트가 내 개발 DB 인지 `.env.local` 을 확인한다. 아무것도 쓰지 않았다 |
| 확정 Rev N건이 있습니다 … `--allow-delete-confirmed` | 예전 가상 계획에 확정 Rev 가 있어 지우려면 트리거를 잠시 꺼야 한다. **개발 DB 이고 지워도 되는 가상 계획일 때만** 안내된 명령을 직접 실행한 뒤 `setup:real-data` 를 다시 실행한다. 운영 DB 에서는 절대 쓰지 않는다 |
| 실제 기준정보가 들어 있는 DB 입니다 (db:seed) | 세팅 뒤에는 `npm run db:seed`·`db:reset` 이 막힌다(실제 데이터 보호). 가상 데이터로 되돌릴 때만 `-- --force` |

## 참고

- 교체 계수 기본값은 `config/changeover-defaults.json` 에 있다. 가동률은 파일에 적지 않고 기준표(I65:J73) 둘째 자리 내림으로 계산한다. PET2·PE 는 팀장님 확인 전이라 없다.
- 계수는 마이그레이션으로 바꾸지 않는다(운영 DB 에 자동 적용되지 않게). 이 명령을 실행한 개발 DB 에만 반영된다.
- 개별 명령(`import:operation-plan`, `demo-plan:regenerate`, `demo-plan:clear`)은 그대로 쓸 수 있다.
