## 개발 중 추가로 정한 규칙 (고객 확인 필요)

| 항목 | 적용 규칙 | 설정 |

| 계획 기준일 | "이번 주 목요일"(월~일 기준)부터 15일. 다른 목요일 선택 가능 | 화면 |
| 교체 횟수 집계 | 제품이 전일과 다르고 교체유형이 비어 있으면 교체로 세고 기본 교체유형 손실 적용 + "미입력, 기본값 적용" 주의. 제품이 같아도 교체유형이 입력돼 있으면 입력대로 | `default_changeover_type`=BM |
| 과잉 판정 | 예상재고 > 향후 N일 출고 합계. 제품별 재정의 가능. 향후 출고 0인 제품은 "출고 계획 없음" | `surplus_days`=14, `products.surplus_days` |
| 우선순위 점수 (FR-11) | w1·(1/(최초 부족까지 일수+1)) + w2·대형거래선 + w3·안전재고 미달 | `priority_weights` 3 / 2 / 1 |

## 회의 확인: 교체 시간과 가동률 (2026-11-19, 팀장님 회의 녹음)

| 항목 | 확인 내용 | 적용 |
|---|---|---|
| 풀셋교체(FULLSET) | 인젝션 금형 + 블로우 몰드 둘 다 교체, 5~6시간 | PET1 FULL **6h** (개발 DB 계수는 기준정보 화면에서 직접 변경) |
| B/M교체 | 인젝션은 고정, 블로우 몰드만 교체, 약 2시간 | PET1 BM **2h (추정)** |
| 익일가동 | 기준표의 "익일가동"은 예외 상황일 가능성이 높음 | **확인 중.** 계수표에 켬/끔 옵션은 남김. 켜진 경우에만 교체일 생산 0·"익일" 표시 |
| 계획표 칸 | 칸 한 개 = 하루 24시간. "풀셋 = 하루 전체 손실"이 아님 | 비가동 시간만큼만 손실 |
| 가동률 | 공식 (24 − h)/24 가 아니라 **기준표(주간계획표 '생산1_1STAGE' I65:J73)** 값을 **둘째 자리 내림** | `changeover_factor_table` (원본 값 저장), `lib/engine/changeover.ts` `rateFromLostHours` |
| 기준표 밖 | 0h → 1.00, 10h~24h → (24 − h)/24 둘째 자리 내림 + "기준표 밖" 주의, 24h → 0 | 같은 함수 |

- `0001_init.sql` 기본값(PET1 BM 3h·0.87, FULL 익일가동)은 팀원 DB 호환을 위해 그대로 두었다. 각 DB 에서 기준정보 → 교체 손실 계수로 바꾼다.
- **추가 확인 필요:** 기준표 옆 메모에 PET2 "사출 5HR(0.79)", "2STAGE - BM 2HR + 휴식 3HR = 5HR" 이 있다. 현재 기본값(PET2 BM 2h·FULL 4h)과 다를 수 있다.

## 설계 메모: 비가동 시간 직접 입력과 ④ 다운타임 상태 분류·부분 정지 (구현은 ④ 진행 때)

- 지금: 칸별 `plan_cells.lost_hours_override`(0~24 정수) = 그날 **전체** 비가동 시간. 값이 있으면 교체유형 기준 시간 대신 쓴다.
- ④에서 할 일: `downtimes` 에 사유 분류(고장·정전·점검·휴무 등)와 정지 시간(h, 비우면 하루 전체)을 추가한다.
- 계산 우선순위 (합의됨):
  1. 하루 전체 정지(`downtimes`, 시간 없음) → 생산 0
  2. 칸 직접 입력(`lost_hours_override`) → 그날 전체 비가동으로 대체 (담당자의 최종 수정)
  3. 교체 기준 시간 + 부분 정지 시간 (합계 최대 24h)
  - 결과 시간은 같은 기준표 함수(`rateFromLostHours`)로 가동률로 바꾼다. 열 구조는 바꾸지 않는다.
