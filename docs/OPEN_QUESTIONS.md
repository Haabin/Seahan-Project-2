# 미확정 사항과 적용 중인 기본값

요구사항 정의서 9장의 질문 중 고객 답변 전인 항목은 **코드에 하드코딩하지 않고** `settings` 테이블(기준정보 화면에서 수정 가능)에 둔다. 답이 오면 화면에서 값만 바꾸면 된다.

| 번호 | 질문 | 현재 처리 | 기본값 | 설정 키 / 위치 |
|---|---|---|---|---|
| Q1 | 현행 계획표 사출기 행의 일별 숫자(2.8, 4, 2.4)의 의미 | **확정: 설비별 일일 원료(씨벌크) 소비량, 단위 톤.** 생산배대 `생산2_PET` 시트의 사출 설비(P1~P5, A1) 행에서 읽어 설비·일자별로 저장한다. 값이 있는 날짜·공장은 외부 설비 고정 사용량(Q9) 대신 그 합계를 쓴다. 19행 `원료소비량`은 검산에만 쓴다 | – | `line_resin_usage`, `lib/excel/import-baedae.ts`, `lib/engine/seabulk.ts` |

| Q3 | Capa·수량 단위(본/천본) | 제품 기준정보에 단위 필드, 전역 기본 단위 설정 | EA(본) | `products.unit`, `qty_unit` |

## 개발 중 추가로 정한 규칙 (고객 확인 필요)

| 항목 | 적용 규칙 | 설정 |
|---|---|---|
| 계획 기준일 | "이번 주 목요일"(월~일 기준)부터 15일. 다른 목요일 선택 가능 | 화면 |
| 교체 횟수 집계 | 제품이 전일과 다르고 교체유형이 비어 있으면 교체로 세고 기본 교체유형 손실 적용 + "미입력, 기본값 적용" 주의. 제품이 같아도 교체유형이 입력돼 있으면 입력대로 | `default_changeover_type`=BM |
| 과잉 판정 | 예상재고 > 향후 N일 출고 합계. 제품별 재정의 가능. 향후 출고 0인 제품은 "출고 계획 없음" | `surplus_days`=14, `products.surplus_days` |
| 우선순위 점수 (FR-11) | w1·(1/(최초 부족까지 일수+1)) + w2·대형거래선 + w3·안전재고 미달 | `priority_weights` 3 / 2 / 1 |
| Capa 우선순위 | 호기×제품 Capa → 없으면 제품 기본 Capa | `line_product_capacity`, `products.default_daily_capa` |
| 3~6주 사일로 추정 | 월 운용안 물량 ÷ 가동일수 × 중량, 주말에는 주말 계수 적용 | `monthly_operation_plan`, `weekend_factor` |
| 사일로 2기 | 합계 기준으로 계산·그래프(상한 160t). 기별 실측치는 표에 표시 | – |
| 발주 추천 물량 | 최초 하한 미달일 − 리드타임 = 발주 기한. 리드타임 구간 최저 예상재고를 하한 위로 올리는 양을 입고 단위로 올림 | `lead_time_days`=30, `receipt_unit_ton`=22 |

## v0.4에서 정한 것 (생산배대·재고현황·초안 생성)

아래 Q14~Q16은 **지금 규칙대로 구현했지만 나중에 바뀔 수 있다.** 바뀌면 표의 위치만 고치면 된다.

| 번호 | 질문 | 현재 처리 | 바꿀 곳 |
|---|---|---|---|
| Q14 | 생산배대 교체 네모의 **색**(연분홍 / 빨강)에 의미가 있는가 | **무시.** 두 색을 같은 교체로 본다. 원래 색은 셀의 근거(`plan_cells.basis`)에 남긴다 | `lib/excel/import-baedae.ts` (`changeoverColor`) |
| Q15 | 글자 `HR` 이 든 네모의 의미 | **무시.** 교체로도 메모로도 읽지 않고 개수만 센다 | `lib/excel/import-baedae.ts` (`isHrText`) |
| Q16 | Rev 번호의 출처 | **파일 이름**(`(Rev. 1)` → 1). 시트 안 `[ Rev' 0 ]` 표기는 무시. 파일 이름에 없으면 업로드 화면에서 입력 | `parseRevFromFilename` 한 곳 |

### 사용자 확정 사항

| 항목 | 규칙 | 설정 |
|---|---|---|
| 교체 시간·계수 | 전 공정 Full set 6시간·0.75, B/M 2시간·0.915. 익일 가동 없음. 옛 범례 값(PET1 B/M 3HR, FULLSET 익일가동)은 쓰지 않는다 | `changeover_coefficients`, `changeover_hour_factor_table` |
| 네모 크기 | 가로 폭으로 큰 네모(Full) / 작은 네모(B/M). 기준은 **읽은 시트 전체** 네모 폭을 가장 큰 간격에서 둘로 나눈다 → `생산2_*` 시트 교체는 모두 B/M | – |
| 화살표 | 가로 화살표 = 진행 기간. 칸의 50% 이상 덮으면 생산일, 30~70%는 포함하되 경고. 제품명 칸도 생산일. 빈 칸은 대기 | `baedae_arrow_min_cover`, `baedae_arrow_ambiguous` |
| 실제 데이터 | Supabase 업로드 허용(화면 업로드로만). git 커밋 금지 | `.gitignore` |

### 개발 중 정한 것 (확인 필요)

| 항목 | 적용 규칙 |
|---|---|
| 재고 ↔ 수급 검증 | 수불표를 저장·업로드할 때 동기화 함수(`sync_inventory_from_ledger`)가 제품에 연결된 품목의 일자별 현재고를 `inventory_snapshots`에 써넣는다 |

| 수불표 구간 | 소계 행(`PS 계`, `B2C 계` …) 기준 구간을 따로 저장한다. A열 공정 값과 소계 구간이 일치하지 않기 때문 |
| `생산2_*` 시트 | 읽어서 검증 스크립트·미리보기에 보여주지만 **계획으로 저장하지 않는다**(호기 블록 높이가 불규칙). 원료 소비량만 저장한다 |
| 주문 | `orders` 테이블(출고계획 `shipments`와 별개). 매칭 안 된 주문도 원문 이름으로 보관한다 |
| 금형 모델 | (A) `molds` + `mold_products`(N:M) + `plan_cells.mold_id` |
| 순 소요량 | 기본 켬. 주문 − (현재고 − 안전재고). 납기 빠른 주문부터 재고를 쓴다 |
| 교체유형 학습 | 과거 확정 계획에서 "이 제품 → 저 제품" 전환 때 B/M으로 한 적이 있으면 B/M, Full만 있으면 Full, 이력이 없으면 Full로 가정하고 "확인 필요" |
| 새 제품 등록 | 생산배대 매칭 화면에서 planner도 제품을 등록할 수 있다(수정·삭제는 admin). 새 제품은 Capa가 0이라 기준정보에서 넣어야 초안 생성 대상이 된다 |
